# 仓库边界与实施路线

[返回首页](../README.md) · [完整设计](design.md)

## 当前状态

四个阶段都已交付：

- 本仓库：协议文档、JSON Schema、Node.js / Python / Go 三个 SDK（共用测试向量）、四个示例。
- Polaris：API 令牌与细分 scope、结构化事件与 Webhook、插件安装与页面、远程订阅格式、订阅改写、节点外部指标。

第 4 阶段的订阅改写和外部指标需要面板 0.1.149 及以上；订阅格式需要 0.1.148 及以上。

## 分阶段交付

| 阶段 | 本仓库 | Polaris 宿主 |
| --- | --- | --- |
| 1：API 基础 | 权限与幂等调用约定、版本兼容说明；待接口稳定后增加客户端 | 细分 scope、按令牌过滤 OpenAPI、事务订单去重与并发更新 |
| 2：事件 | 事件 JSON Schema、原始正文签名工具和接收方去重示例 | 结构化事件、事务 outbox、Webhook 租约调度、重试与审计 |
| 3：安装和页面 | 清单 Schema / 校验器、配对与健康约定、通知服务示例 | 安装生命周期、加密配置、权限批准、一级扩展菜单、iframe / 用户入口 |
| 4：扩展接口 ✅ | [`sub-format`](../examples/sub-format)、[`tcp-ping`](../examples/tcp-ping) 示例；SDK 的 `parseSigned`、`checkTransform`、`checkMetric`、`reportMetrics`；共用向量 `testdata/extensions.json` | 远程订阅格式、受限节点改写、独立指标权限与路由（Polaris #187、#188、#189） |

每一阶段须分别提交可审阅的开发 PR，注明对应宿主 PR 和协议修订。只有运行验证完成后，文档才将能力标为可用。

## 依赖方向

外部插件 → 本仓库的版本化协议 / SDK → 宿主公开 HTTP API。

本仓库不导入 Polaris 的 `internal` 包，不连接宿主数据库，也不依赖私有专业版源码。SDK 已实现并有测试，但尚未发布到包仓库；请拷贝文件或用 git 依赖。

如宿主以后引入本仓库的公共包，应固定发布版本；可复用校验和签名逻辑可外置，宿主鉴权、事务、数据库迁移及后台任务生命周期继续由 Polaris 管理。

## 导航和兼容

面板插件入口为一级「扩展」，位于「域名与证书」之后、「系统」之前。其 UI 和管理路由在宿主实现。

协议仍为草案。字段或签名行为调整需同时更新设计、示例和配套测试；发布前建立明确的宿主协议版本和最低兼容版本，不能用示例中的版本号代替真实支持声明。
